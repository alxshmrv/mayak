# Как участвовать в разработке

Спасибо за интерес к Маяку. Особенно полезны воспроизводимые баг-репорты,
улучшения объяснимости результатов и аккуратные дополнения к локальному
обнаружению устройств.

## Перед началом

- Для вопросов и небольших предложений сначала создайте issue.
- Для уязвимостей используйте приватный порядок из `SECURITY.md`.
- Не публикуйте реальные SSID, BSSID, IP, MAC, имена устройств, базы данных и
  необработанные диагностические логи.
- Проверяйте сетевые функции только в сетях, которыми вы владеете, управляете
  или имеете явное разрешение тестировать.

## Локальный запуск

Нужны Rust 1.88+ и Node.js 22.12+. Для macOS также требуются macOS 15+ и Xcode
Command Line Tools; для Windows — 64-битная Windows 10/11, Microsoft C++ Build
Tools и WebView2 Runtime. Подробности — в
[матрице платформ](docs/PLATFORMS.md).

```bash
npm ci
npm run tauri dev
```

## Проверки перед pull request

```bash
npm run check
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --all-targets
```

Для изменений нативной интеграции также соберите приложение на затронутой
платформе:

```bash
# macOS
npm run tauri build -- --bundles dmg

# Windows
npm run tauri build -- --bundles nsis,msi
```

Обычная сборка текущей платформы:

```bash
npm run tauri build
```

macOS не компилирует Windows FFI-модули, а Windows не компилирует мост
CoreWLAN. Изменения в `src-tauri/src/native/`, `src-tauri/src/platform/`,
`build.rs` или platform-specific конфигурации должны пройти CI обеих
платформ.

## Требования к изменениям

- Один pull request решает одну понятную задачу.
- Поведение, влияющее на риск, доверие или классификацию устройств, покрывается
  тестами и объясняется в интерфейсе.
- Новые сетевые проверки должны иметь жёсткие таймауты, ограничение
  параллелизма и оставаться внутри текущей локальной подсети.
- Запрещены перебор паролей, эксплуатация уязвимостей и обход контроля доступа.
- Новые зависимости требуют объяснения и совместимой open-source лицензии.
- Пользовательский текст пишется по-русски; имена кода и комментарии — по
  принятому в проекте английскому стилю.

## Документация и релизы

- Пользовательское изменение добавляется в `CHANGELOG.md`.
- Новое платформенное поведение отражается в `README.md`,
  `docs/PLATFORMS.md`, а при необходимости — в `PRIVACY.md`.
- Версия синхронизируется в `package.json`, `src-tauri/Cargo.toml` и
  `src-tauri/tauri.conf.json`.
- Тег `v*` запускает сборку DMG, NSIS и MSI. Публикуйте тег только после
  зелёного CI на macOS и Windows.
- Updater-релиз требует `TAURI_SIGNING_PRIVATE_KEY` и
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` в GitHub Actions Secrets. Приватный ключ
  никогда не добавляется в Git.
- Workflow держит релиз черновиком, пока не собраны обе платформы и не
  проверены `latest.json`, подписи и SHA-256.
- Готовые assets проверяются по приложенным SHA-256; GitHub-архивы исходников
  не являются установщиками.
- Полный порядок выпуска и ротации ключа описан в
  [release runbook](docs/RELEASING.md).

Отправляя вклад, вы соглашаетесь распространять его на условиях лицензии MIT
проекта.
