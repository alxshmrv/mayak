# Как участвовать в разработке

Спасибо за интерес к Маяку. Особенно полезны воспроизводимые баг-репорты,
улучшения объяснимости результатов и аккуратные дополнения к локальному
обнаружению устройств.

## Перед началом

- Для вопросов и небольших предложений сначала создайте issue.
- Для уязвимостей используйте приватный порядок из `SECURITY.md`.
- Не публикуйте реальные SSID, BSSID, IP, MAC, имена устройств, базы данных и
  необработанные диагностические логи.
- Проверяйте сетевые функции только в сетях, которыми вы владеете, управляете
  или имеете явное разрешение тестировать.

## Локальный запуск

Нужны macOS 15+, Xcode Command Line Tools, Rust 1.88+ и Node.js 22.12+.

```bash
npm ci
npm run tauri dev
```

## Проверки перед pull request

```bash
npm run check
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --all-targets
```

Для изменений нативной интеграции также соберите приложение:

```bash
npm run tauri build
```

## Требования к изменениям

- Один pull request решает одну понятную задачу.
- Поведение, влияющее на риск, доверие или классификацию устройств, покрывается
  тестами и объясняется в интерфейсе.
- Новые сетевые проверки должны иметь жёсткие таймауты, ограничение
  параллелизма и оставаться внутри текущей локальной подсети.
- Запрещены перебор паролей, эксплуатация уязвимостей и обход контроля доступа.
- Новые зависимости требуют объяснения и совместимой open-source лицензии.
- Пользовательский текст пишется по-русски; имена кода и комментарии — по
  принятому в проекте английскому стилю.

Отправляя вклад, вы соглашаетесь распространять его на условиях лицензии MIT
проекта.
